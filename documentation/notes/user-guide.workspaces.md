## What A Workspace Is

A workspace is a directory Kato is allowed to write captured conversations
into. It has:

- a `.kato-workspace-config.yaml` file in the workspace root;
- a registered alias such as `default`;
- optional display name metadata for operator surfaces;
- output defaults such as directory, filename template, timezone, shared tags, markdown frontmatter, and writer flags.

## Create A Workspace

```bash
kato workspace init [<dir>]
```

If `<dir>` is omitted, Kato uses the current directory.

## Register A Workspace

```bash
kato workspace register [<dir>] --alias <alias> --name <display-name>
```

If `--alias` is omitted, Kato uses the leaf folder name. If `<dir>` is omitted,
Kato uses the nearest ancestor workspace config from the current directory.

By default, registration restarts the daemon when it expands
`allowedWriteRoots`, because an already-running daemon may not have permission
to write into the newly registered workspace yet. Use `--no-restart` only when
you intend to restart later.

## List And Unregister

```bash
kato workspace list
kato workspace unregister <alias-or-id>
```

Unregistering removes the alias from Kato's registry. It does not delete the
workspace directory or its captured output files.

## Workspace Config

`kato workspace init` creates `.kato-workspace-config.yaml` with keys like:

```yaml
autoRecordConversations: false
autoRecordRoots: []
defaultOutputDir: "."
filenameTemplate: "{timestampHumane}-{snippetSlug}-{provider}.md"
workspaceTimezone: "local"
defaultTags: []
tagSuggestions: []
markdownFrontmatter:
  includeFrontmatterInMarkdownRecordings: true
workspaceFeatureFlags:
  writerIncludeCommentary: true
  writerIncludeThinking: true
  writerRelativizeLocalLinks: true
  writerUseDendronStyleWikilinks: false
```

The exact scaffold is generated by the installed Kato version. Use
`kato workspace init` rather than hand-writing a new file from memory.

Timestamp tokens (`{timestampHumane}`, `{YYYY}`, `{YY}`, `{MM}`, `{DD}`,
`{HH}`, `{mm}`) reflect the conversation's most recent activity — the newest
timestamped event in the conversation at the moment the destination is
resolved — rather than the wall-clock time the record or capture command ran.
Recording an older conversation therefore yields a filename dated to that
conversation, and two conversations recorded in the same minute keep distinct
timestamps. When no event timestamps are available, the command time is used.

## Edit Workspace Config In Kato Web

On the Kato Web Workspaces page, use `Edit` on a registered workspace to update the shared `.kato-workspace-config.yaml` fields for output directory, filename template, workspace timezone, shared default tags, shared tag suggestions, markdown frontmatter toggles, and writer flags including relative local links and Dendron wikilinks.

`autoRecordConversations` can also be edited there. When enabled, Kato automatically records matching Claude conversations. By default a conversation matches when its working directory is inside the workspace root; `autoRecordRoots` (one directory per line in the edit form) extends matching to conversations whose working directory is inside any listed root — typically the project repos whose conversations belong in this workspace.

Each workspace row on the Workspaces page also shows the resolved auto-record state without opening the edit form: `auto-record on`, `auto-record off`, or `auto-record unavailable` when the workspace config cannot be resolved.

Kato Web writes the supported workspace config schema back in Kato's canonical YAML shape. Unknown keys and invalid values are rejected, and a currently invalid workspace config is shown as an error until the file is repaired.

## Display Labels And Usernames

Workspaces can have operator-facing display labels. Kato Web also lets you set preferred participant usernames and personal tag suggestions per workspace; those personal choices live in user config, not the shared workspace file.

## Dendron Workspaces

When `writerUseDendronStyleWikilinks` is enabled, Kato discovers nearby
`dendron.yml` context from the output path and rewrites eligible local note
links to Dendron wikilink syntax. Non-note files and assets remain regular
markdown links, with local absolute paths sanitized to relative paths by
default.
